# v0.4 Controlled Pilot Governance

StructuraX v0.4 adds a **reference-only** human governance layer above the deterministic v0.1/v0.2 controls and the offline v0.3 AI adapter boundary. It does not deploy a service, grant model autonomy, approve documents, mutate ERP state, or establish production fitness.

## Review workflow

A review case binds an exact evidence artifact SHA-256 to an exact workflow-policy SHA-256. Workflow actions are appended as immutable hash-linked audit events. Each event records only a digest of its payload; raw document content is prohibited from the audit contract.

The state machine is fail-closed:

`draft -> submitted -> in_review -> approved|rejected`

A reviewer may request changes, returning the case to `changes_requested`; only the original requester can resubmit. Terminal states cannot transition.

## RBAC and maker-checker

Roles are explicit: requester, reviewer, approver, security, privacy, and release manager. Approval requires a role listed in the bound policy. If the policy names approval owners, an approver outside that owner list is rejected. The case creator cannot approve their own case.

No workflow event carries operational side-effect authority. An approved review case is evidence of a human decision inside the reference workflow only; it is not a payment instruction, deployment command, regulatory determination, or production authorization.

## Policy versioning and change governance

Every policy version records:

- a policy identifier and semantic version;
- separate human author and approver identities;
- a change-ticket identifier;
- an effective timestamp;
- the exact SHA-256 of the superseded policy, when replacing a prior version.

`validate_policy_replacement()` rejects policy substitution when the replacement does not bind the exact predecessor digest, does not advance the version, changes the policy ID, or becomes effective before the predecessor.

## Audit-chain properties

`verify_audit_chain()` requires contiguous sequence numbers, exact case/policy binding, exact predecessor hashes, and recomputed canonical event digests. Any mutation to an earlier event invalidates the chain.

The reference implementation is append-oriented evidence logic, not a claim that an external database is immutable. A real pilot must enforce append-only/retention controls in its actual storage and IAM layers.

## Synthetic reference data

`configs/pilot_policy.json`, `datasets/workflow/reference_case.json`, and `datasets/workflow/reference_events.json` are synthetic fixtures generated by `scripts/build_pilot_reference.py`. They demonstrate the contract without representing real people, approvals, systems, or production evidence.
